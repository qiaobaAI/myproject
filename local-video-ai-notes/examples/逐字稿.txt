[00:00] 大家好，这一节我们来认识一下 Java 并发包里一个"地基"级别的东西——AQS。
[00:06] 它的全称特别长，叫 AbstractQueuedSynchronizer。
[00:12] 这个名字看着吓人，其实你把它的三个单词拆开，每个都很直白。
[00:18] 第一个词 Abstract，意思是抽象的。
[00:22] 也就是说，你没法直接 new 一个 AQS 来用，它得靠你写一个子类去继承它，才能真正干活。
[00:30] 第二个词 Queued，队列。
[00:33] 它内部是用一个先进先出的队列，来管理那些"想拿锁但还没拿到"的线程的。
[00:41] 第三个词 Synchronizer，同步器。
[00:44] 说白了，它就是用来实现"线程之间怎么协调、怎么排队等锁"这么一个东西的。
[00:52] 所以合起来，AQS 就是一个"基于队列的、抽象出来的同步框架"。
[00:59] 那你可能会问，Java 不是已经有 synchronized 关键字了吗，为什么还要搞一个 AQS？
[01:07] 这就得说说它解决的痛点了。
[01:10] 早期的 synchronized 是一把"死等"的锁——
[01:15] 你没抢到锁，线程就一直阻塞挂起，啥也干不了，中间还不能取消、不能中断。
[01:23] 而 AQS 在更底层提供了一套"可中断、可超时、可取消"的排队机制。
[01:31] 你等得不耐烦了，可以中途放弃去干别的事，回头再来抢，这在 synchronized 里是做不到的。
[01:39] AQS 还支持两种重要的工作模式。
[01:43] 第一种叫排它模式，也叫独占模式。
[01:47] 这个好理解，就像家里的卫生间——同一时刻只能一个人用，别人都得在门口排队。
[01:56] ReentrantLock 就是典型的独占锁。
[02:00] 第二种叫共享模式。
[02:03] 它允许"一定数量的线程"同时进去工作。
[02:07] 比如 Semaphore 信号量，你设置允许十个线程并发，那第十一个才需要排队。
[02:15] 这就像小区门口的共享车位，有十个空位时大家都能进，满了才要等。
[02:22] 所以记住一句话：AQS 是 Java 并发包的底层骨架，
[02:28] 像 ReentrantLock、Semaphore、CountDownLatch 这些，全都是站在 AQS 肩膀上实现的。
[02:37] 理解了 AQS，你就等于拿到了理解整个 Java 锁机制的钥匙。
[02:43] 这一节的概念就先到这儿，下一节我们去看它内部的队列到底是怎么排队的。
