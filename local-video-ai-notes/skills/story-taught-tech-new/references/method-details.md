# 方法细节参考（method-details）

本文件是 `SKILL.md` 的补充明细，仅在需要对照表 / 反模式 / 自检逐条核对 / 降级举例时查阅。

## 一、故事类型选择（单概念揭晓模式）

| 概念的核心特征 | 推荐故事类型 |
|---------------|-------------|
| 两方博弈 / 冲突 | 古代寓言 |
| 渐进累积的过程 | 日常生活 |
| 系统行为 / 涌现现象 | 自然现象或机械装置 |
| "表面 vs 实际"的反差 | 角色对话或说明书场景 |
| 本质是"为解决某问题而存在"（工具/方案型，如 Node.js、缓存、依赖注入） | 对比式结构：先"没有它"的困境，再"有它"的变化 |

选择标准：
- 故事的"冲突/转折"必须精准映射概念的核心矛盾
- 2~3 个角色，一条核心情节线

## 二、叙事语气对照表

| 概念的情感色彩 | 推荐语气 | 示例场景 |
|---------------|---------|---------|
| 告诫/警示（技术债务、死锁） | 沉稳、略带惋惜 | 说书人风格，娓娓道来 |
| 揭示/反直觉（抽象泄漏、幸存者偏差） | 轻快、有反转感 | 像在讲一个"你猜怎么着"的故事 |
| 权衡/两难（CAP 定理） | 中立、不偏袒 | 平实叙述，让读者自己判断 |
| 机制/原理（依赖注入） | 日常、接地气 | 生活化口吻，拉近距离 |

> 简单概念豁免：讲"什么是变量""什么是循环"等基础概念时，默认用日常接地气语气即可，不必逐条对照上表。表格主要用于需要情感引导的复杂/抽象概念。

## 三、反模式黑名单（完整表）

| 反模式 | 表现 | 为什么失败 | 正确做法 |
|--------|------|-----------|---------|
| **角色傀儡化** | 角色做出违背自身设定的事来配合隐喻 | 读者感觉人物不真实，故事崩塌 | 先构思角色的合理动机，再寻找与概念的巧合相似，而非反过来 |
| **隐喻过度** | 每个细节都对应概念，故事像密码本 | 变成说明书，失去趣味 | 只映射核心要素，其余细节服务故事生动性 |
| **揭晓过早** | 开头或中段就说"这就像 XXX 概念" | 毁掉悬念，读者不再去"悟" | 忍住——让故事自己说完，揭晓放最后 |
| **故事空洞** | 故事没有冲突、没有张力 | 没有情感就没有记忆 | 确保有明确的困境、选择或转折，让读者关心角色 |
| ⚠️ **概念曲解** | 为让故事好看而歪曲概念核心含义 | 最致命的错误，读者学到错误理解 | 自检：只读故事不读释义，形成的理解是否正确？ |
| ⚠️ **隐喻比概念更抽象** | 用魔法符文解释抽象泄漏、用修仙体系解释设计模式 | 读者需先解码隐喻本身，门槛不降反升 | 用"奶奶测试"，换成日常场景（万能遥控器、翻译器出错） |
| **全程抽象无具体主角** | 通篇概括，没有一条 mov 指令 / 一个快递贯穿 | 记不住，像在读教科书摘要 | 重写成"某某的一生"式叙事 |

## 四、7 条自检明细（单概念揭晓模式）

1. **角色自然度**：去掉概念，角色的行为在故事逻辑里是否合理？为隐喻做出不合常理的举动 → 重写
2. **隐喻准确性**：核心冲突是否映射概念的**核心矛盾**（而非边缘特性）？实际写出的情节是否忠实复现写作前确认的映射？若读者懂了故事却没懂概念 → 隐喻跑偏
3. **故事独立性**：抛开概念，故事本身是否有趣、可读？只是"披着故事皮的说明书" → 重写
4. **揭晓时机**：概念名是否在故事自然结束后才出现？开头或中段出现 → 太早
5. **简洁度**：隐喻点是否在 3~5 个（核心要素对应 ≥2）？有无可删的冗余情节？
6. **具象化**：隐喻载体是否通过"奶奶测试"？载体本身需要解释（魔法、修仙、科幻设定）→ 换日常场景
7. **术语闭环**：专业释义是否引入读者可能不熟悉的新术语？有 → 末尾用 1~2 句简要说明

> 最多重写 2 次；仍不通过则输出当前最佳版本并诚实说明不足。

## 五、降级策略详解

1. **先找最具体的侧面**：哪怕概念整体抽象，也尝试定位其中一个有实体的侧面来讲。
2. **场景类比（短比喻）**：概念不适合完整故事时，用短比喻代替。例：
   > 解释"递归" → "就像你站在两面镜子之间，看到的是一层套一层的无限影像——每一层都和前一层一样，只是更小。但总有一个'最小'的你站在最深处，当光线到达那里时，反射开始一层层往回走。这就是递归。"
3. **缩小范围**：概念太宽泛（如"面向对象编程"）→ 建议用户拆成更小的概念（"封装""多态"）。
4. **诚实告知**：找不到用户熟悉的合适场景时，坦白而非硬编——"这个概念我暂时没想到你熟悉的场景来类比，换一个更日常的场景来讲可以吗？"

系统链路模式降级：若目标系统找不到结构同构的日常类比世界，退回"分模块单概念揭晓"，把链路拆成若干单概念分别用模式 B 讲解。

## 六、反馈处理细节

- **"隐喻不太准确"** → 回到 Step 1/承重墙，重新确认核心矛盾是否理解正确，调整隐喻映射
- **"这个故事不好/换一个"** → 回到故事类型与语气选择，换一种类型和语气重新创作
- **"太隐晦/太直白"** → 调整三段式结构中揭晓时机的早晚，或增减铺垫篇幅
- **"故事太长/太短"** → 调整铺垫部分的细节量，不改变核心结构
- **多概念请求**：
  - 概念之间存在对比关系 → 可用一个故事串两个概念（两个角色分别代表 A 和 B，通过不同结局体现差异），结尾分别揭晓
  - 概念之间无直接关联 → 建议分开讲两个故事
  - 不确定 → 先确认："这两个概念我用一个对比故事来讲，还是分开讲？"
